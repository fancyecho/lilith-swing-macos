# 皮肤引擎

皮肤引擎的目标是让窗口机制保持稳定，同时允许每套秋千拥有完全不同的视觉语言。

## 三个渲染组件

1. **Seat**：可见且可交互的座板。皮肤必须保留明确的水平上沿；同一顶边的实际游戏承托由窗口引擎单独管理。
2. **Vine**：左右各一个窄窗口，由座板连接到屏幕顶部；素材可垂直重复，并接受从上向下的揭示进度。
3. **Top ornament**：位于桌面可用区域顶端的浅窗口，负责处理藤蔓突然出现时的视觉过渡。

`main.m` 负责窗口生命周期、拖动、保存位置和揭示动画。`WindowEngine` 管理兼容置顶与透明承托几何。`SwingSkin` 协议只暴露视觉尺寸指标与三个绘制入口。

## 目录约定

每套内置皮肤使用独立目录：

```text
Skins/<SkinName>/
  skin.json
  <SkinName>Skin.h
  <SkinName>Skin.m
  Assets/
```

`skin.json` 保存：

- 稳定标识和显示名称；
- 座板窗口大小；
- 藤蔓窗口宽度；
- 顶部冠饰窗口高度；
- 左右连接点；
- 素材文件与 AppKit 左下角坐标系下的裁切矩形。

渲染类负责组合这些素材。这样同一张高分辨率素材可以提供座板、花章或局部纹理，而不会要求主程序理解皮肤内部细节。

## 窗口尺寸约束

莉莉丝会把满足最小尺寸的系统窗口边界当作表面。座板宽度应满足该条件；藤蔓和顶部冠饰必须至少有一个维度低于游戏阈值。

从 v1.3.2 起，兼容模式保留 `seatWindowSize` / `seatHeight` 作为视觉与交互尺寸（穆夏仍为 248 × 104 pt），不通过拉伸皮肤解决支撑问题。独立承托窗口保持相同顶边、宽度，并向下延伸至屏幕底部；它不绘制内容且完全穿透鼠标。可见座板不进入游戏的普通窗口扫描，避免同一位置出现两个座位。

当前在 Retina 主屏幕上验证的安全上限为：

- 藤蔓宽度不超过 28 pt（56 backing pixels）；
- 顶部冠饰高度不超过 28 pt（56 backing pixels）。

修改指标后应同时运行窗口探针和实际游戏验证。

## 添加新皮肤

1. 新建 `Skins/<SkinName>/` 与 `Assets/`。
2. 创建 `skin.json` 并定义指标和素材。
3. 实现 `SwingSkin` 协议的三个绘制入口。
4. 在 `SwingSkinRegistry.m` 注册皮肤。
5. 在 `build.zsh` 中加入渲染源与资源复制。
6. 使用预览工具检查明暗背景，再检查莉莉丝的窗口识别。

未来若皮肤只更换纹理、不改变组件排版，可以复用已有渲染类，仅新增清单和素材。

## 穆夏 · 鸢尾

首套皮肤采用新艺术运动常见的细长鞭状曲线、对称花章与鸢尾。v1.3 针对 248 pt 的实际显示尺寸重新收敛层级：座板使用浅蜜色木材、象牙、鼠尾草绿与旧金，只保留一个中央花章和少量大曲线；顶部冠饰则改为为 28 pt 浅窗口单独生成的完整横向素材，不再拼接容易被屏幕边缘裁切的局部花章。高分辨率素材由 OpenAI 图像生成能力制作，窗口中的裁切、重复、连接和动画由原生 AppKit 完成。
