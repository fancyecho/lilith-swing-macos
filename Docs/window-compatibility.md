# 窗口兼容与置顶

## 问题与证据

在 macOS 27 的本地测试中，莉莉丝站在秋千上时切换窗口可能被弹飞，完全坐稳后不受影响。旧实现的座板处于普通层级，每 0.8 秒重新置前；记录显示，其他窗口被点击后，座板会短暂退到后面，再被定时器移回前面。游戏日志同时出现异常速度与位置重置，而秋千几何位置不变。

这些证据支持“窗口排序变化影响游戏的支撑碰撞体”这一解释；游戏是闭源软件，尚未直接验证其碰撞体映射实现。坐稳状态会冻结角色位置，也解释了站立与落座的差异。

直接把 `NSWindow.level` 从 0 提高到 1 虽能置顶，但实际游戏诊断中秋千不再出现在可用窗口列表，因此不采用这个方案。

## 兼容方案

`WindowEngine/SwingWindowPolicy.m` 把可选的子层级接口隔离在一个适配器内：

- 游戏承托窗口的公开层级仍为 `NSNormalWindowLevel`（0），保留游戏识别能力。
- 自身窗口的子层级设为 1，保持在普通窗口前面；莉莉丝的浮动层级 3 仍在秋千前面。
- 删除周期性重新置前的定时器；显示、拖动结束等生命周期操作仍可按需置前。
- 窗口不成为主窗口或键盘焦点，藤蔓、冠饰与独立承托继续穿透鼠标。
- 菜单“兼容置顶（实验性）”可关闭该策略，隐藏扩展承托并把可见座板恢复到普通层级，作为对照模式。

适配器动态解析 `SLSMainConnectionID` 与 `SLSSetWindowSubLevel`，只传入本程序创建的窗口编号。不存在跨进程注入、系统配置修改或游戏文件改动。若接口缺失或返回失败，窗口仍为普通层级，菜单提示当前不可用；不会回退到会破坏游戏识别的层级 1。

参考：[Apple 窗口层级说明](https://developer.apple.com/documentation/appkit/nswindow/level-swift.struct)、[yabai 的子层级调用](https://github.com/asmvik/yabai/blob/master/src/osax/payload.m)。适配器为独立实现，未复制这些项目的实现代码。

## v1.3.2：坐姿支撑扩展

用户确认 v1.3.1 不再乱飞，但秋千抬高后会在落座后很快下落。连续五次日志显示，角色成功落座后约 0.76–0.78 秒，`SeatWatcher` 两次采样都检测不到脚下承托，报告 `SupportLost`，随后解除坐姿并主动起坠。这些落座均未绑定有效窗口句柄，走物理检测兜底路径。

当时可见窗口为 248 × 104 pt，而坐姿根节点相对座位顶边下移约 158.7 pt，已在短矩形下方。由此提出“坐姿定位点离开承托区域”的假设；它需要实际游戏验收，不能仅靠坐标计算判定修复成功。

现在由 `SwingSupportFrameForSeat` 保持顶边和宽度，将透明承托向下延伸到当前主屏幕底部，避免把某个角色缩放值写死。坐姿点落到屏幕地面时由地面承托；仍在屏幕内时处于扩展矩形中。可见座板仍为原来的 248 × 104 pt，不更换素材、不拉伸皮肤。

- `Lilith Swing Seat`：层级 0 / 子层级 1，独立透明承托，是唯一游戏座位；`ignoresMouseEvents = YES`，不接收任何鼠标操作。
- `Lilith Swing Artwork`：层级 1，保持原来的画面与拖动范围；游戏不会把它当作第二个座位，莉莉丝的层级 3 仍在它前面。
- 拖动时实时更新承托矩形但保留窗口编号；隐藏秋千同时隐藏承托，不在原位置留下幽灵平台。
- 关闭兼容模式或接口不可用时，隐藏透明承托、把可见座板退回层级 0，恢复普通短座板行为。

这里使用 AppKit 的[整窗鼠标穿透](https://developer.apple.com/documentation/appkit/nswindow/ignoresmouseevents)，不是仅对某个视图返回空命中结果，也不靠定时切换鼠标拦截状态。

## 边界与验证

这是私有接口兼容方案，不受 Apple 稳定性保证。后续系统或游戏更新需重新验证，不能把一次通过视为所有机器均兼容。全屏空间、系统菜单和其他置顶应用不属于普通窗口置顶承诺。

`zsh test.zsh` 检查真实窗口工厂的层级、焦点、透明度、空间行为、开关、鼠标穿透、坐姿位置覆盖、拖动同步与定时器移除。`zsh test.zsh --window-server` 额外创建四个宽度 20 pt 的透明测试窗口，连续检查“模拟桌宠 > 可见座板 > 透明承托 > 反复置前的普通窗口”，并覆盖隐藏/显示及移动；这些窗口不接收输入，尺寸低于游戏的表面阈值。

游戏验收必须另外完成：

1. 把莉莉丝拖到秋千上方，确认仍可站立和坐下。
2. 站立、尚未进入坐姿时，交替点击两个其他应用窗口。
3. 确认无弹飞、重置，且秋千窗口顺序保持稳定。
4. 分别检查已坐稳、拖动秋千、隐藏/显示后的行为。
5. 在远离屏幕底部的位置落座后至少观察 20 秒，确认不再出现 `SupportLost`。
6. 点击座板下方扩展区域中的其他窗口，确认鼠标正常穿透。

仅编译通过、窗口顺序测试通过，都不能代替最后这组游戏验收。

## 本机验收记录（2026-09-03，v1.3.2）

- 几何、鼠标穿透配置、拖动同步、隐藏状态与回退策略测试通过；30 次真实窗口顺序测试通过。
- 实际画面窗口仍为 248 × 104 pt，同一位置的游戏承托扩展为 248 × 378 pt；顶边与横向位置未改变。
- 游戏在之前会掉落的同一高度成功落座，随后连续 200 多次检测命中承托，观察段内没有 `SupportLost`、坐姿退出或异常速度重置。
- 用户按“落座后观察约 20 秒，再点其他窗口，并检查下方点击”的步骤确认：能坐稳，下面的窗口也能点击。
- 本次通过只代表当前机器与游戏版本，后续系统、游戏或角色缩放变化仍需复查。
